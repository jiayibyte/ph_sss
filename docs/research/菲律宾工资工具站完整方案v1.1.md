### 1.2 修正项（执行时覆盖 PRD 原文）

**修正 1：关键词吃自己（cannibalization）— 必须修**
PRD 把 `how to compute sss contribution` 同时分配给了 §4.1 表格页（同页覆盖清单）和 §4.2 计算器页（目标关键词），且表格页内嵌的 Salary Lookup 本身就是个计算器，两页功能重叠。
**修正**：关键词硬分配——表格页独占 `table / 2026 / monthly contribution` 系词；计算器页独占 `calculator / how to compute` 系词。表格页的 Salary Lookup 组件保留（体验好），但页内主 CTA 指向计算器页；两页 H1/Title/首段不得互相蹭词。

**修正 2：Holiday Pay 恢复独立页 — PRD 降级错了**
PRD 依据「50/月」把 holiday pay 塞进 overtime 页当一个 mode。与 Phase 0 实测矛盾：
- 该词 SERP 全是公司级内容投入（Sprout / InCorp / Forvis Mazars 都在维护指南）——没人为 50 量级的词做这种投入；
- 这是全场唯一「有搜索、前排零交互工具」的缺口，是差异化主武器；
- 菲律宾一年约 18 个法定/特别节假日，**每逢节前都有「这天上班工资怎么算」的脉冲**，查询落在 "holiday pay rules + 节日名/日期" 等变体上——KP 的 50 是 exact 词量级，不是簇量级。
**修正**：恢复 `/holiday-pay-calculator/` 独立页（P1），功能 = 选节日类型（Regular / Special Non-working / +Rest Day）× 是否上班 × 时薪 → 倍率拆解；配一个「今年节假日 + 对应倍率」年历区块，**每逢大节前 1–2 周更新一次**（真实新鲜度）。Overtime 页保留 holiday 作为输入维度不冲突（意图不同：一个按节日查倍率，一个算加班费总额）。

**修正 3：新增税后工资计算器 — PRD 漏了旗舰复合工具**
竞品 taxcalculatorphilippines.com 恰恰是靠 take-home/tax calculator 起家反向吃下 contribution 词群的。净工资 = 工资 − SSS − PhilHealth − Pag-IBIG − BIR 预扣税，**天然复用全部四个已建引擎、天然是全站内链枢纽**。
**修正**：新增 `/take-home-pay-calculator/`（P1），目标词 `tax calculator philippines / take home pay calculator philippines / salary calculator philippines`；结果卡逐项列四险一税拆解，每项链回对应工具页。

**修正 4：OEC 与 PRC 的难度评级下调**
PRD 把两者标为「SERP 难度：高」。Phase 0 实测相反：OEC 前排是政府 PDF、Weebly、Scribd、AI 农场博客（极弱）；PRC 前排官方+媒体仅占 2 位、其余全独立站且 lisensyaprep 一站双位。
**修正**：难度改为「低-中」，预期回报上调；P2 标签保留（内链权重排序，两页与其余页面同批一次做完）。

**修正 5：搜索量数字的口径标注**
PRD 的 50,000 / 5,000 / 500 / 50 是 Keyword Planner 的**量级桶**（区间代表值），不是精确月量；PRD 声称的 "v6.0 SERP 复核" 无法独立验证。
**修正**：所有量级数字视为优先级排序依据而非承诺；上线后以 GSC 实测 impressions 重排优先级（v3 证据分级纪律）。Phase 0 我方独立 SERP 实测与 PRD 的 P0 排序交叉印证一致（SSS table 🟢、缴费表全绿、13th month 🟡），排序可信。

### 1.3 补全项（PRD 缺失，从 v3 移植）

| 缺失 | 补全 |
|---|---|
| 技术栈/部署 | **Astro 静态生成**（构建产物为纯静态 dist/，计算器用 React 岛屿组件，规则 JSON 构建期注入）→ **部署到自有服务器 + 自有 CDN**（不用 Cloudflare）：nginx 托管静态文件；HTML 设短缓存/ETag（缴费表要年更、节前更新），`/_astro/*` 指纹资产设长缓存 immutable；必须 HTTPS + brotli/gzip。**⚠️ 节点位置检查项**：目标用户在菲律宾、爬虫是 Googlebot——CDN 须有东南亚/海外边缘节点且源站海外可达；若服务器/CDN 仅大陆节点，菲律宾访问延迟和收录都会受损（境内 CDN 还涉及备案），务必确认 |
| 发布窗口 | 唯一的日期约束（不是排期）：**13th month 词群 11–12 月爆发，10 月中前上线并完成收录**，一次性交付正好赶得上 |
| 分发对冲 | Facebook 主页（菲律宾第一渠道）：发缴费表变更、节假日工资倍率提醒、13th month 到账季科普——每月 2–4 帖即可，对冲 Google 单渠道 |
| 90 天验证门槛 | 移植 v3 的 Go / Pivot / Stop（详见第四章） |
| 结构化数据 | 如实标注：工具页 WebApplication + FAQPage（FAQ 须是真问题）；表格页加 Dataset 可选；**不做任何夸大 schema** |
| 移动端基线 | 菲律宾移动端约 60.8%（Statcounter 2026-07），HR/payroll 人群 PC 占比可观——两端都要过 Core Web Vitals，验收以移动端为准 |

## 二、品牌与域名（已验证，2026-08-19）

### 最终决定：用已持有的 **aytool.com**，品牌 **AyTool** ✅

用户已持有 aytool.com——经 Wayback Machine 全历史核查（2002–2025 共 20+ 年快照）：绝大部分时间是空页/停放页/302 跳转，**无垃圾站、无站群使用痕迹 → 无历史惩罚风险**；同时也无外链积累（无红利，中性起点）。

为什么可以直接用：
- 域名含不含关键词对排名影响极小（EMD 加成早已弱化）；**主题聚焦靠内容不靠域名**——竞品 philpad.com 用完全不相关的品牌名照样统治缴费表词群；
- **品牌巧合可以讲成本地故事**：「Ay!」（Ay nako!）是菲律宾人最高频的感叹词，AyTool 对菲律宾用户天然可读可记；
- 已持有 = 零采购摩擦，今天就能开工。

使用条件（硬性）：
1. 站内内容 **100% 菲律宾 payroll 主题**，不放任何无关工具——泛工具箱化会稀释主题信号；
2. 将来做南非/印度站**另起独立域名**（按 v3 原则每国一站），aytool.com 专属菲律宾；
3. 全站 tagline 钉死定位：`AyTool — Philippine Payroll & Contribution Calculators (Independent)`。

**品牌 slogan（已定）**：`Ay! May tool para diyan.`（"那事儿有工具"，本地化转写 "There's an app for that"）
- 成立点：连读音 = AyTool（slogan 即品牌记忆装置）；"Ay!" 是菲律宾最高频感叹词；Taglish 混搭自然；diyan 用规范拼法。
- **使用边界**：slogan 管性格不管定位——只用于首页 hero、页脚、OG 分享图；`<title>` / meta description / H1 等 SEO 与信任位一律用描述性定位语，不得被 slogan 挤占。
- 上线前找 1–2 位母语者做 5 分钟校验（与印度板块的母语校验纪律同源）。

### 备选（如果以后想换更本地化的品牌）：**SahodCalc** — `sahodcalc.com` ✅（Verisign RDAP 确认可注册）

理由：
- **Sahod**（发薪/到手工资）是菲律宾人对工资的日常用词，本地共鸣强于 PRD 建议的 PayTools/SalaryTools（无地域感的英文泛词）；
- 与在位竞品的 **sweldo 系**品牌（sweldongpinoy.com、sweldoph.com、suweldocalculator.com）天然区分——同语义、不同词根，不撞车不侵权；
- sahod.ph 早在 2017 年就被人注册（本次 whois 实查），侧面印证词根价值；
- 9 字符 + 品类词 calc，.com 年费约 $10（Cloudflare Registrar 成本价）。

### 候选清单（本次全部实查）

| 域名 | 状态 | 备注 |
|---|---|---|
| **sahodcalc.com** | ✅ 可注册 | **首选** |
| sahodhub.com | ✅ 可注册 | 备选：以后扩 OEC/PRC 等非计算器内容时包容性更好 |

| sahod.ph | ❌ 已注册（2017） | — |
| payrollph.com | ❌ 已注册 | — |

### 关于 PinoyCheck（v3 时期的旧推荐）为什么不再用
pinoycheck.com 是 v3 做「政务办事查询站」定位时起的名——**「Check」品牌指向 status 查询**，而那正是本方案刻意避开的仿官方灰区（NBI/status checker 站群带）；现在定位已收窄为 payroll 计算器，Check 语义错配。名字本身没问题，是定位变了。

### 决策小结
**aytool.com（已持有）直接开工**；sahodcalc.com 作为可选升级（本地语感更强、词根含品类，但差距不大，不构成阻塞）；paytools.ph 仅在坚持 .ph 地域信号时考虑（dot.ph 官方 whois 确认可注册，年费明显贵于 .com）。全站页脚放 PRD §8 的 not-affiliated 声明。

P0/P1/P2 标签保留，但含义从「排期批次」改为**内链权重与首页排位的优先级**（P0 五件套占首页首排卡片、获得最多内链）。上线后运营动作只剩两类：按官方节奏更新规则 JSON（年更 + 节前 holiday 年历），以及按 GSC 数据决定扩哪些长尾页。

### 数据正确性纪律（在 PRD §15 之上加一条）
四个缴费引擎的规则 JSON 在上线前**逐条对照官方来源人工复核一遍**（SSS Schedule / PhilHealth advisory / Pag-IBIG circular / DOLE），并在 /methodology/ 写明核验日期。算错缴费额比没有流量更致命——错误数字被引用会招官方与用户双重反噬。

## 四、90 天验证门槛（从 v3 移植，Phase 1 起算）

- **0–30 天**：只看索引率、GSC impressions、各集群非品牌 query 是否出现。不以收入为 KPI。
- **31–60 天**：只扩有 impression 的集群；缴费表有信号 → 扩人群维度长尾（ofw/voluntary/self-employed 已是自动补全实证词）；13th month 有信号 → 扩 per-scenario 页（mid-year hire 等）。
- **61–90 天 Go / Pivot / Stop**：
  - **Go**：organic clicks 连续增长 + 一批 Top 20–50 query + ≥2 个工具持续获流 → 扩到 60–80 页，考虑第二市场复制（南非 MzansiCheck 用同一套引擎架构）
  - **Pivot**：有 impression 无点击 → 改 Title/意图、强化工具、页面合并
  - **Stop**：90 天几乎无非品牌 impression → 停簇不恋战

### 达标预期（口径与 v3 一致，不做时间承诺）
目标日均 1000 自然访问 ≈ 单一 P0 词群做进前 3 即可覆盖（sss table 量级桶 50K/月）；13th month 季节脉冲可能单月直接冲破目标。参照 Flippa 验证锚点（同市场 philhealthportal 月 UV 6.5 万），量级天花板足够。

## 五、风险与红线（合并双方，全文有效）

1. PRD §1 非目标 + §8 隐私条款原文执行；每页 not-affiliated 声明。
2. 不注册、不使用含 sss/philhealth/pagibig/dole 的域名或子域（philhealthportal.com 的教训：落在官方打假类别内的站，流量再高也是负资产）。
3. 缴费数字禁止从竞品站抄（PRD §4.5 原话），一律官方来源 + 版本化。
4. 时效页只跟官方更新节奏走，不制造假新鲜度；holiday 年历按官方 Proclamation 更新。
5. KP 量级桶不外化为承诺；一切以 GSC 实测重排。
